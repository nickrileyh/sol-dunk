# SOL DUNK

A Flappy Dunk-style skill betting game paid in SOL. Tap to flap a winged basketball down through rings; swishes pay more than rim hits, swish streaks pay more each time, and every 6th (gold) ring is a checkpoint where the player cashes out or keeps going.

## This repository is the source of truth

Several chats work on this game. Start every session from a fresh clone of `nickrileyh/sol-dunk`, and commit and push when you finish, so the next chat builds on your work instead of an older copy.

The playable demo is a claude.ai artifact, slug `fb718710-5b6b-4ad8-bf8e-4d9cee1b68b6`; publish `dist/index.html` there. Before publishing, check that its live version is the one you started from. If another session published since, split that build with `python3 tools/split_build.py <file> <dir>`, merge its changes into `src/`, and push them here. Never publish over someone else's work.

## Keeping every copy in sync

The game lives in four places, and they should always hold the same build:

1. `src/` on `main`, the source of truth.
2. `dist/index.html`, `dist/index.server.html` and the root `index.html`. `npm run build` writes all three. GitHub Pages serves the root `index.html` at https://nickrileyh.github.io/sol-dunk/ and updates a minute or two after each push.
3. The claude.ai demo artifact, published from `dist/index.html`.
4. The "Live version" line in the claude.ai project doc `claude/sol-dunk-design.md`, which gives the artifact version and the repo commit it was built from.

Finish every change in this order:

1. `git fetch` and rebase onto `origin/main`, since another chat may have pushed.
2. Call `get_artifact` on the demo. If its version isn't the one you started from, `read_artifact` it and run `npm run check -- <the file it saved to>`. If the check says the repo doesn't have that build, split it with `tools/split_build.py`, merge it into `src/` and push that first.
3. `npm run build`, then the checks under Rules.
4. Commit `src/` and the three builds together, and push.
5. Publish `dist/index.html` to the artifact.
6. Update the doc's "Live version" line with the new artifact version and commit.
7. `read_artifact` again and run `npm run check -- <that file>`. It should end with "everything is in sync".

`npm run check` on its own checks that the three builds match `src/` and that nothing is uncommitted or unpushed. Given a saved copy of the demo, it also says whether the demo is this commit's build, an older commit's (publish) or a build the repo doesn't have (merge it).

Never publish a build you haven't pushed, and don't push a game change without publishing it, so the demo and GitHub Pages always match.

## Layout

- `src/engine.cjs`: deterministic 120 Hz physics, level generation, replay and payout helpers. The client, simulator and server share it.
- `src/paytable.cjs`: generated by `sim/calibrate.cjs`. Never edit it by hand.
- `src/bot.cjs`: the human-like autopilot used by the simulator and the lobby demo.
- `src/pots.cjs`: challenge pot rules (challenges, daily UTC window, progress from verified ring outcomes, rake, split, rollover), shared by the client, the server and the demo pot.
- `src/missions.cjs`: daily and weekly missions (UTC windows, targets, XP, SOL rewards, the play that unlocks them, progress from verified levels), shared by the client, the server and the demo.
- `src/special.cjs`: the special level (recipes, the generator, the daily rotation, prizes written by `sim/special.cjs`), shared by the client, the server and the simulator.
- `src/game.js`, `src/index.html`, `src/style.css`: the browser client.
- `build.cjs`: inlines everything into `dist/index.html` (demo) and, with `SERVER_URL=/`, `dist/index.server.html` (real SOL).
- `sim/`: Monte Carlo runner and calibrator; `sim/special.cjs` prices the special level. `server/`: Express API with Solana deposits and withdrawals and replay verification. `tools/`: Playwright browser checks.

## Rules

- **Physics changes need new payouts.** Any change to `src/engine.cjs` (physics, level settings) means bumping `VERSION`, then running `node sim/run.cjs` (about 11 minutes; `node sim/run.cjs 1 <tier> merge` re-runs one tier). After that, run `node sim/calibrate.cjs patterns.json --mode edge --write` (`npm run calibrate`). Wait for "wrote sim/out/patterns.json" before calibrating. Then re-price the special level with `npm run special` (about 5 minutes); also after any change to the bot or a recipe in `src/special.cjs`. Never edit its `PRIZES` block by hand.
- **House edge (mode `edge`):** the house keeps an edge at every checkpoint against average and good players. An average player gets back at most 90% at checkpoint 1 and loses at least 10% on every later level; a good player gets back at most 99% at checkpoint 1 and 97% from checkpoint 2 on. Pros aren't capped by default: they clear the easy levels so reliably that capping them (`--cap-pro 0.99 --cap1-pro 1.01`) shrinks the top prizes to a few × on Rookie and Pro. Check the "RTP by skill" and "Best possible win" tables in the calibration output; the lobby shows each tier's real best possible win.
- **Challenge pots:** the house's only edge on a pot is its cut of every entry (`POTS.RAKE`, 10%); never let the house take a side. A challenge is judged only from a run's verified ring outcomes (the server's replay), only for runs started after entering, and only on the challenge's tier or harder. Money in open pots counts as owed to players in the server's cover check. Change a challenge's `p` (the simulator's per-run chance by skill) when the physics or the challenge changes; the demo's simulated entrants use it.
- **Special level:** a fixed prize for clearing every ring of a fresh course; the house's edge is that the prize is priced so a good player gets back at most 97% (at the clear rate's upper 97.5% bound), so never raise a prize above what `sim/special.cjs` writes. Pros come out ahead on a fixed prize, so accounts the server flags for beating the house can't enter. Its rings never count toward missions or the pot; its entry counts as play for mission SOL.
- **Mission SOL:** every run counts toward daily and weekly missions whatever the bet; a window's SOL pays only once the player has played its need in that window (run bets and special entries). The rewards add up to at most half the house's smallest edge against a good player (1%) across days and weeks together (`MS.RATE`, 0.5%), so a good player who plays just enough to collect still loses. Raise the need to raise the rewards; don't raise the shares.
- **Before publishing:** `npm run build && SERVER_URL=/ node build.cjs`, `npm test` (server), `python3 tools/flows.py`, `python3 tools/features.py`, `python3 tools/contact.py`, `python3 tools/pot_flow.py`, `python3 tools/ui.py`, `python3 tools/special_flow.py`, `python3 tools/missions_flow.py` and `npm run check`. After camera or spacing changes, `python3 tools/speed.py` reports how much of the next ring is in view deep into a run.

## What the owner has asked for (keep these)

- A dark, clean, Apple-like look. One backdrop for every level, with no per-level colour themes.
- Apple-style layout and navigation (the owner asked for a much cleaner, sleeker look): black pages with large titles in the system font, the live arena in a rounded window on Play and in the Locker, an iOS tab bar docked to the bottom, pages that push in with a back button, and sheets with a grabber and Done. Flat fills only: no glows, gradient text, floodlights or display fonts. The Play tab holds only the title, the balance, the arena window, tier, bet and one Play button; everything else lives in the other tabs.
- The checkpoint card must not describe how much harder the next level is.
- Amounts read as "SOL" text. Don't draw the Solana logo; the owner can drop the official icon in as `src/sol-icon.svg`.
- Original art only: no Flappy Dunk assets.
- Rim hits shouldn't carry the ball forward strongly: after a knock, the forward push fades back in (engine `RECOVER`).
- As the ball speeds up, the rings spread out with it, so deeper levels never leave less time between rims (engine v9). Make deep levels harder in other ways.
- The ball and rim tube are 10% larger than in v9 (engine v10). Rings widen only enough to keep the gap the ball fits through the same, so the difficulty didn't change.
- Rings never sit too low: ring centres stay between y 220 and 500, so even a bobbing ring's lowest point is 152 units above the floor (engine v11; the limit was 540).
- The house keeps an edge deep into a run, against strong players too: never price a level so that good players come out ahead at any checkpoint. Elite players are covered by the challenge pots instead of smaller prizes.
- Challenge pots (the owner asked for them): alongside regular play, players can buy an entry into the day's pot; everyone who completes the challenge in a run splits it, and the house keeps 10% of every entry, so it earns from every player however skilled. In the demo the other entrants are simulated and labelled so.
- Fair rims: a ball that touches the rim with its centre over the opening drops in; it only bounces out when it comes down on or past the end of the rim (engine v12, `SETTLE_*`). Keep the difficulty in the pace and the geometry, not in unlucky bounces.
- The ball is drawn at exactly its hitbox size, and rings at exactly their collision size.
- Better navigation, more customization and missions (the owner asked for these): a tab bar (Play, Challenges, Missions, Locker, Profile), six locker categories (ball, wings, flame, trail, rims, court) plus a player card, and daily, weekly and career missions. Mission progress and XP never depend on bet size. Courts stay dark and are one backdrop for every level; rim colours never touch the gold checkpoint ring or the grey missed ring.
- An organized layout (the owner asked for it): everything has one home and no menu is duplicated. Pages (How to play, Odds & fairness, Wallet, Trophies, Recent runs) push in over the current tab with a back button; sheets are only for tasks (editing the player card); settings live on Profile, so the top bar is just level, balance and mute. Scrolling pages fade out under the top bar instead of showing through the capsules.
- Missions pay SOL, so players play more to earn them (the owner asked for this): daily and weekly missions pay SOL once the window's play reaches its need (2 SOL a day, 10 a week by default), priced inside the house's edge (see Rules). Career missions pay XP and items only.
- The pot has its own page (the owner asked for this): the Daily pot side of the Challenges tab, where you enter it too.
- A special level challenge (the owner asked for it): a generated special level each day; the player pays an entry and wins a SOL prize for clearing it. Each attempt is a new course from its own provably fair seed, the same recipe for everyone that day, one backdrop like every level.
